Worker setup

Set up this worker PC

    This PC runs jobs for your team. Five things have to be true before it can — this checklist makes each one visible instead of letting the box come up looking healthy and quietly doing nothing.

    • The cloud address this worker leases jobs from.
    • An enrolment token — mint it in the panel under Fleet → Add worker.
    • Two keys: one so this box can store its own identity, one so it can run the AI.
    • Which platforms this PC is allowed to run.
    • A signed-in Chrome for each browser platform you picked.

    You can close this at any time. Nothing here is destructive, and the worker stays visible to your admins the whole way through — including while it is parked.

    Point this worker at the cloud it should lease jobs from.

    Saving starts the worker. It is normal for it to fail to reach your cloud at first — this app talks to it locally, so you can finish setup either way.

    Two secrets live only on this PC. They are written to a 0600 file next to the config and are never sent anywhere.

    Which platforms may this PC run?

    A box that advertises nothing is never sent work — and it makes your team's readiness banner say "ready" when it is not. You cannot continue with none picked.

    That second check is the one that catches a Chrome which looks alive and is not — it answers on the port while refusing every attach. If it is red, quit that Chrome completely (do not just reload a tab) and launch it again from here.

    Sign in to each platform inside the Chrome window this app opens — 2FA and all. Nothing is typed into this app; it reads the browser's own session and the badge turns green by itself.

    Skip a platform if its badge is wrong — the LinkedIn and X session signatures are not yet confirmed against a live account, so a red badge there may be the check being wrong rather than your login. A skip lets you finish setup; it is remembered only until you quit this app, is never sent to your cloud, and never hides the warning from your admins.
